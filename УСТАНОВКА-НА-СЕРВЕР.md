# TenderPilot на ваш VPS (Нидерланды) — пошагово

Ваш сервер подходит полностью. Единственная особенность: ЕИС (zakupki.gov.ru) не отвечает
иностранным адресам, поэтому для живого поиска закупок нужен российский прокси.
Сайт, база, ИИ и все остальные площадки работают напрямую. Прокси настраивается в разделе 6.

```
Браузер → https://ваш-домен → VPS в Нидерландах (TenderPilot в Docker)
                                   └─ только запросы к zakupki.gov.ru → российский прокси
```

---

## 0. Что понадобится

- IP-адрес сервера и пароль root (или SSH-ключ) — в письме от хостера.
- Домен (необязательно, но с ним будет адрес вида `https://tenders.ваш-домен.ru`).
- 15 минут времени. Всё остальное скрипт сделает сам.

---

## 1. Подключиться к серверу

**Windows 10/11** — ничего ставить не нужно, SSH уже встроен:

1. Нажмите **Win + R**, введите `cmd`, Enter.
2. Напишите (подставьте свой IP):

```
ssh root@185.10.20.30
```

3. На вопрос `Are you sure you want to continue connecting?` напишите `yes`, Enter.
4. Введите пароль root — **символы при вводе не отображаются**, это нормально, просто вставьте
   или напечатайте и нажмите Enter.

Появится приглашение вида `root@server:~#` — вы на сервере.

> Если хостинг дал не root, а другого пользователя (`ubuntu@…`) — добавьте перед командами `sudo`.
> Если SSH-доступ не через пароль, а по ключу — в панели хостера есть готовый «Web Console»,
> можно работать прямо в браузере.

## 2. Установка одной командой

Скопируйте строку целиком, вставьте в чёрное окно (правая кнопка мыши в Windows-терминале
вставляет текст) и нажмите Enter:

```
curl -fsSL https://raw.githubusercontent.com/bobra2019-dot/tenderpilot/main/install-vps.sh | bash
```

Скрипт сам: поставит Docker и git → скачает проект в `/opt/tenderpilot` → соберёт контейнер →
запустит → дождётся ответа → откроет порты → напечатает адрес и пароль.

Занимает 3–6 минут. В конце увидите примерно такое:

```
============================================================
 TenderPilot установлен
============================================================

 Открыть:  http://185.10.20.30:8000
 Вход:     owner@zavod.ru  /  demo1234   <-- смените пароль сразу
```

Откройте этот адрес в браузере на своём компьютере. Всё — приложение работает
круглосуточно и перезапускается само после падения или перезагрузки сервера.

**Если нужен другой порт** (например, 8080 уже занят):

```
PORT=8080 bash -c "$(curl -fsSL https://raw.githubusercontent.com/bobra2019-dot/tenderpilot/main/install-vps.sh)"
```

### Если сайт по IP не открывается

Порт закрыт файрволом хостера (так настроено у многих). В панели хостинга найдите
**Firewall / Security Group / Сеть** и разрешите входящий TCP на порт **8000** (и 80, 443 для домена).
Сам сервер уже настроен, дело только в панели.

## 2.1. Если на сервере уже работают другие проекты

Установщик TenderPilot **не удаляет и не настраивает чужие сервисы**. Он делает ровно четыре вещи:

| Действие | Что именно | Чем рискуют другие проекты |
|---|---|---|
| ставит Docker (если его нет) | пакеты docker-ce через get.docker.com | ничем: ничего не удаляется и не обновляется из ваших сервисов |
| создаёт папку проекта | `/opt/tenderpilot` (меняется через `TENDERPILOT_DIR`) | если папка занята **другим git-репозиторием**, скрипт остановится и ничего не тронет |
| запускает один контейнер | публикует только порт 8000 | если 8000 занят, скрипт остановится и предложит `PORT=8080` |
| открывает порт в файрволе | `ufw allow 8000/80/443` — только разрешения | ничем: правила только добавляются, запреты не меняются |

Чего скрипт **не делает**: не трогает `/var/www`, `/home`, базы данных, чужие Docker-контейнеры,
не удаляет пакеты, не перезапускает nginx/apache/php, не меняет чужие конфиги.

### Проверить заранее, свободен ли порт

```
ss -ltnp | grep ':8000'
```

Пусто — можно ставить. Что-то есть — ставьте на другой порт:

```
PORT=8080 CLOUD=1 bash -c "$(curl -fsSL https://raw.githubusercontent.com/bobra2019-dot/tenderpilot/main/install-vps.sh)"
```

### Если на сервере уже есть nginx или apache (важно для раздела 5)

**Не устанавливайте Caddy** из раздела 5 — он займёт порты 80/443 и уронит ваши сайты.
Вместо этого добавьте TenderPilot как ещё один сайт в существующий nginx:

```
nano /etc/nginx/sites-available/tenderpilot
```

```nginx
server {
    listen 80;
    server_name tenders.ваш-домен.ru;

    client_max_body_size 60m;          # для загрузки выгрузок площадок

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```
ln -s /etc/nginx/sites-available/tenderpilot /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

Сертификат: `apt install certbot python3-certbot-nginx && certbot --nginx -d tenders.ваш-домен.ru`
(certbot сам допишет SSL в конфиг вашего сайта и не тронет остальные).

Чтобы приложение не было доступно напрямую по IP, в `docker-compose.yml` замените
`"${PORT:-8000}:8000"` на `"127.0.0.1:8000:8000"` и выполните `docker compose up -d`.

### Если нужно полностью убрать TenderPilot

```
cd /opt/tenderpilot && docker compose down
rm -rf /opt/tenderpilot          # база в data/ удалится — сначала сделайте копию
```

Docker и ваши другие контейнеры при этом остаются на месте.

## 3. Первые 10 минут после входа

Войдите под `owner@zavod.ru` / `demo1234` и сразу:

1. **Смените пароль** — кнопка «ключ» в левом нижнем углу.
2. **Настройки ИИ** → вставьте ключ (OpenAI, Anthropic, DeepSeek или OpenRouter) → «Проверить ключ».
3. **Профиль завода** → номенклатура, ОКПД2, регионы, экономика завода.
4. **Администрирование** → включите «Требовать моё подтверждение», чтобы чужие не зашли.
5. **Источники данных** → включите «ЕИС • 44-ФЗ», впишите ключевые слова (например
   `задвижка, затвор, арматура`), укажите прокси (раздел 6 ниже) → «Собрать сейчас».

## 4. Управление сервером (три команды, которые нужны чаще всего)

```
cd /opt/tenderpilot && docker compose logs -f --tail 100     # логи
cd /opt/tenderpilot && git pull && docker compose up -d --build   # обновить до новой версии
cd /opt/tenderpilot && docker compose restart                # перезапустить
```

**Резервная копия** (база + выгрузки в один архив):

```
cd /opt/tenderpilot && tar czf /root/tenderpilot-$(date +%F).tar.gz data inbox
```

Раз в неделю достаточно. Восстановление: распаковать архив обратно в `/opt/tenderpilot`.

## 5. Домен и HTTPS (рекомендую)

Без домена сайт работает по `http://IP:8000`, но браузер будет ругаться на «небезопасно»,
а пароль пойдёт по сети открытым текстом. С доменом и сертификатом — всё как у нормальных сайтов.

**5.1. Направьте домен на сервер.** В панели, где куплен домен (reg.ru, timeweb, namecheap…),
добавьте DNS-запись:

| Тип | Имя | Значение |
|---|---|---|
| A | `tenders` (или `@` для самого домена) | IP вашего VPS |

Подождите 5–30 минут, пока запись обновится.

**5.2. Поставьте Caddy** — он сам получит HTTPS-сертификат и будет пускать трафик в приложение:

```
apt install -y caddy
nano /etc/caddy/Caddyfile
```

Удалите всё содержимое и впишите (заменив домен на свой):

```
tenders.ваш-домен.ru {
    reverse_proxy 127.0.0.1:8000
}
```

Сохранить в nano: `Ctrl+O`, Enter, `Ctrl+X`. Затем:

```
systemctl restart caddy
systemctl status caddy --no-pager
```

Сайт открывается по `https://tenders.ваш-домен.ru` с зелёным замком.

**5.3. Привяжите домен к приложению** (чтобы в Telegram-уведомлениях были правильные ссылки):

```
cd /opt/tenderpilot
sed -i 's|^PUBLIC_URL=.*|PUBLIC_URL=https://tenders.ваш-домен.ru|' .env
docker compose up -d
```

**5.4. Закройте прямой доступ по IP** (по желанию): в `docker-compose.yml` замените
`"${PORT:-8000}:8000"` на `"127.0.0.1:8000:8000"` и выполните `docker compose up -d`.
После этого сайт доступен только через домен и Caddy.

## 6. ЕИС из Нидерландов: российский прокси

`zakupki.gov.ru` блокирует зарубежные адреса. Прокси нужен **только** для запросов к ЕИС.

### Вариант А — второй, самый дешёвый VPS в России (200–300 ₽/мес)

Подойдёт любой тариф Timeweb, Selectel, Reg.ru, Beget с Ubuntu. На нём:

```
apt update && apt install -y squid
```

Откройте `/etc/squid/squid.conf` (`nano /etc/squid/squid.conf`), найдите строку
`# http_access deny all` и прямо **перед** ней вставьте три строки
(вместо `185.10.20.30` — IP вашего нидерландского сервера):

```
acl nlserver src 185.10.20.30
http_access allow nlserver
```

Затем:

```
systemctl restart squid
```

Проверка с нидерландского сервера (должен вернуться HTML-код страницы ЕИС):

```
curl -s -o /dev/null -w "%{http_code}\n" --max-time 20 -x http://IP-РОССИЙСКОГО-СЕРВЕРА:3128 https://zakupki.gov.ru/
```

`200` или `302` — прокси работает.

### Вариант Б — готовый прокси

Купите российский прокси (datacenter/residential, 200–500 ₽/мес) — выдадут строку вида
`http://логин:пароль@185.10.10.10:8888`.

### Куда вписать прокси

**В интерфейсе (проще):** «Источники данных» → «ЕИС • 44-ФЗ» → поле
**«Прокси для ЕИС»** → вставить строку → «Сохранить настройки» → «Собрать сейчас».

**Или в конфигурации** (действует на все проверки):

```
cd /opt/tenderpilot
nano .env        # добавить строку: EIS_PROXY=http://логин:пароль@185.10.10.10:8888
docker compose up -d
```

Проверьте кнопкой **«Проверить доступность площадок»** в «Источниках данных»:
ЕИС должен стать «доступен». Остальные площадки (B2B-Center, ТЭК-Торг, Росатом) работают
из Нидерландов и без прокси.

> Если прокси нет вообще — всё равно можно работать: загружайте выгрузки площадок
> (CSV/Excel) и XML ЕИС из кнопки «Скачать XML» на карточке закупки. Этот путь работает
> из любой страны, прокси не нужен.

## 7. Если что-то не так

| Симптом | Причина и решение |
|---|---|
| Сайт по IP не открывается | порт закрыт в панели хостера: разрешите TCP 8000 (Security Group / Firewall) |
| `docker compose up` ругается на занятый порт | `PORT=8080` в `.env` или в команде запуска |
| В журнале: «ЕИС не отвечает зарубежным адресам» | не указан прокси (раздел 6) |
| Caddy: «connection refused» | приложение не запущено: `cd /opt/tenderpilot && docker compose ps` |
| Сайт открылся, лента пустая | сбор ещё не запускался: «Источники данных» → «Собрать сейчас» |
| Хочу перезапустить всё с нуля | `cd /opt/tenderpilot && docker compose down && docker compose up -d --build` |
| Нужны логи | `cd /opt/tenderpilot && docker compose logs -f --tail 100` |
| Забыл пароль владельца | `cd /opt/tenderpilot && docker compose exec tenderpilot python -c "from app import db; c=db.connect(); c.execute('UPDATE users SET pass_hash=? WHERE email=?', (db.hash_pass('новыйпароль'), 'owner@zavod.ru')); c.commit()"` |

## 8. Безопасность — сделайте один раз

1. Смените пароль `owner` (кнопка «ключ»).
2. В «Администрировании» включите «Требовать моё подтверждение» — заявки не будут
   активироваться сами.
3. Настройте вход по SSH-ключу и смените пароль root (в панели хостера есть гайды).
4. Поставьте домен и HTTPS (раздел 5) — пароль не будет ходить открытым текстом.
5. Резервная копия раз в неделю (раздел 4).
