# TenderPilot — закрытая CRM для автопастера тендеров

Прототип закрытой платформы для владельца завода: настраиваете профиль производства один раз — система мониторит закупки на площадках, ИИ читает ТЗ, сверяет требования с вашими возможностями, считает маржу и выдаёт вердикт «идём / спорно / не идём».

**Доступ:** http://localhost:8000 → `owner@zavod.ru` / `demo1234`

---

## Что уже работает

| Блок | Что делает |
|---|---|
| **Профиль завода** (5 шагов) | Название, ИНН, регион, направления производства (7 отраслевых каталогов с ОКПД2), продукция текстом, коды ОКПД2, сертификаты/декларации, лицензии и СРО, регионы поставки, опыт, производственный цикл, мин./макс. сумма заказа, экономика (материалы, труд, накладные, логистика, БГ, резерв на риски, минимальная и целевая маржа), веса скоринга |
| **Мониторинг площадок** | ЕИС (44/223-ФЗ), Росэлторг, Сбер А, Фабрикант, B2B-Center, ЭТП ГПБ, ТЭК-Торг + корпоративные порталы: Газпром, РЖД, Росатом, СИБУР, Норникель. Кнопка «Сканировать площадки» подтягивает новые закупки, всё пишется в журнал событий |
| **Лента тендеров** | Фильтры по вердикту, площадке, категории, закону, этапу; сортировка по соответствию / дедлайну / сумме / марже; поиск по названию, заказчику, номеру и **тексту ТЗ** |
| **Ручной «пастер»** | Вставка ссылки, текста извещения или файла ТЗ (**docx / pdf / txt**): парсер вытаскивает сумму, ОКПД2, закон, площадку, регион, срок поставки, дедлайн и требования — создаёт карточку и сразу отправляет в ИИ |
| **ИИ-заключение** | Что подходит и почему, проверка каждого требования ТЗ (выполнено / частично / нет), риски по уровням, признаки ограничения конкуренции («заточка»), вероятность победы, рекомендуемая цена и запас на торг, что готовить в заявку, следующие шаги, вопросы заказчику |
| **Экономика** | Себестоимость по вашим процентам + коэффициент логистики по региону + стоимость банковской гарантии + резерв на риски + НДС/УСН, маржа в рублях и %, безубыточная цена, потребность в оборотном капитале. Живой калькулятор «а если» |
| **Воронка и аналитика** | Этапы (новый → на проверке → готовим заявку → подана → выигран/проигран/отклонён), дашборд с топом рекомендаций и ближайшими дедлайнами, аналитика по площадкам, распределение вердиктов, win rate |
| **Печать заключения** | Кнопка «🖨 Заключение» — печатная версия карточки для внутреннего согласования |

### Как считается оценка

Скоринг = взвешенная сумма: ОКПД2 (30%), совпадение по ТЗ (25%), объём к мощности (15%), география (10%), сроки (10%), сертификаты (10%) — веса настраиваются.

Вердикт:
- **Не идём** — нет обязательного сертификата/допуска/опыта, маржа ≤ 0 или профиль не совпадает.
- **Спорно** — профильное и маржинальное, но есть незакрытые требования по срокам/документам, либо соответствие ниже 72.
- **Идём** — соответствие ≥ 72, маржа выше вашего минимума, все требования закрыты.

## Подключение реального ИИ

Войдите → **Настройки ИИ** → провайдер, модель, ключ → «Проверить подключение».

Поддерживаются:
- **OpenAI** — `https://api.openai.com/v1`, модель `gpt-4o-mini`
- **DeepSeek** — `https://api.deepseek.com/v1`, `deepseek-chat` (самый дешёвый для объёмов)
- **OpenRouter** — один ключ на Claude / GPT / Gemini / Qwen
- **Anthropic** — native API (`claude-sonnet-4-5`)
- **GigaChat** (Сбер) — для РФ-контура
- **Свой сервер** (vLLM / Ollama / LM Studio) — любой OpenAI-совместимый `base_url`, данные не уходят наружу

Ключ хранится в базе на сервере и **никогда не отдаётся в браузер**. Без ключа система полностью работоспособна: скоринг, проверка требований и маржа считаются встроенным движком (в интерфейсе это честно помечено «встроенный расчёт»). С ключом к этому добавляется чтение ТЗ, поиск «заточек», оценка конкуренции и рекомендации.

## Запуск

### Windows — самый простой способ

1. Скачайте проект: на странице GitHub зелёная кнопка **Code → Download ZIP**.
2. Распакуйте архив (правая кнопка на файле → «Извлечь все»).
3. Зайдите в получившуюся папку и запустите **`start.bat`** двойным кликом.
   Скрипт сам найдёт Python, поставит библиотеки, создаст базу и откроет браузер.
   Сообщения в окне — на английском: cmd в Windows ломает русский текст
   внутри bat-файлов, поэтому вывод намеренно англоязычный.

Если Python не установлен — скачайте с [python.org](https://www.python.org/downloads/)
и при установке отметьте галочку **«Add python.exe to PATH»**.

### Если pip ругается на Microsoft Visual C++ / pyyaml

Такое бывает, когда установлен самый новый Python (например 3.14): для него
ещё нет готовых пакетов, и pip пытается собрать их из исходников — а для этого
нужен компилятор C++. В проекте это уже обойдено: в `requirements.txt` только
пакеты с готовыми сборками, установка идёт с флагом `--only-binary=:all:`.

Если ошибка всё же появилась — поставьте **Python 3.12**: для него готовые
пакеты есть для всего. Скачайте «Windows installer (64-bit)» на
python.org/downloads/release/python-3129/ и установите с галочкой
«Add python.exe to PATH». `start.bat` сам выберет 3.12, даже если 3.14 тоже стоит.

### Linux / macOS

```bash
cd tenderpilot
./run.sh                  # поставит зависимости и запустит сервер
# или вручную
pip install -r requirements.txt
python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Откройте **http://localhost:8000**, вход: `owner@zavod.ru` / `demo1234`.

Сброс демо-данных: удалить `data/tenderpilot.db` и перезапустить.

Технологии: Python 3 + FastAPI + SQLite (без ORM), фронтенд — ванильный SPA без сборки и CDN, поэтому работает даже в закрытом контуре.

## Как показать приложение по ссылке (временный хост)

Нужно продемонстрировать сайт человеку, у которого нет вашего компьютера?
Поднимите туннель — получите публичный https-адрес без регистрации и настройки сервера.

```bash
# 1. в одном терминале — само приложение
./run.sh            # на Windows: start.bat

# 2. во втором терминале — публичная ссылка
./tunnel.sh
```

Через 5–15 секунд в выводе появится строка вида
`https://что-то-случайное.trycloudflare.com` — её и отправляйте.

Что важно знать про такой адрес:

- он **временный**: живёт, пока запущены туннель и приложение; ссылка меняется при каждом запуске;
- **никакой авторизации на уровне ссылки нет** — любой, у кого она есть, увидит демо-систему
  и сможет войти с демо-логином. Для показа это нормально, для реальных данных — нет;
- перед показом реальному заказчику смените пароль демо-пользователя и не заносите
  в систему настоящие коммерческие данные.

Для постоянного адреса нужен не туннель, а нормальный деплой: сервер (VPS), домен,
Caddy/Nginx с сертификатом, Postgres вместо SQLite, авторизация по корпоративным аккаунтам.

## Что в прототипе имитация, а что станет реальным

**Уже настоящее:** профиль, скоринг, проверка требований, экономика, парсер текста/файлов, LLM-анализ, воронка, аналитика, авторизация.

**Сбор закупок — уже реализован** (раздел «Источники данных»): живой поиск ЕИС по 44/223-ФЗ, разбор официального XML ЕИС, папка `inbox` с выгрузками площадок (CSV/Excel), API ЭТП по договору, дедупликация, автоотсев ИИ, расписание и Telegram-уведомления. Что осталось на продакшен:

1. **ЕИС** — официальные открытые данные: FTP/выгрузка XML по 44-ФЗ и 223-ФЗ (`zakupki.gov.ru`), плюс ежечасная инкрементальная синхронизация; файлы ТЗ скачиваются по ссылкам из извещения.
2. **ЭТП (Росэлторг, Сбер А, Фабрикант, B2B-Center, ЭТП ГПБ, ТЭК-Торг)** — официальные API/web-сервисы по договору аккредитации; часть площадок отдаёт данные только по закупкам, где вы аккредитованы.
3. **Корпоративные порталы** (Газпром, РЖД, Росатом) — собственные реестры закупок + API групп.
4. Планировщик (Celery/RQ + cron) → нормализация в единую схему → дедупликация по (площадка, номер) → фильтр по ОКПД2/ключам → очередь на LLM-анализ (с кэшем и лимитом токенов) → уведомления (Telegram/email) по вердикту «идём».

**До продакшена обязательно:** авторизация по корпоративным аккаунтам + роли (владелец / тендерный отдел), шифрование ключей (KMS), аудит-лог, Postgres вместо SQLite, очередь задач, резервное копирование, разграничение доступа к ТЗ (NDA).

**Оценка сроков до продакшена:** MVP на реальных данных ЕИС — 3–4 недели; мультиплощадочная версия с ролями и уведомлениями — 2–3 месяца.

## Пользователи, роли и администрирование

У каждого пользователя **своя лента закупок и свой профиль завода** — данные не пересекаются.
Роли:

| Роль | Что может |
|---|---|
| **Администратор** (`owner`) | всё + панель «Администрирование»: пользователи, подтверждение заявок, блокировка, роли, сброс паролей, настройки регистрации |
| **Менеджер по тендерам** (`manager`) | своя лента, профиль, источники, ИИ, уведомления — без панели администратора |
| **Наблюдатель** (`viewer`) | только просмотр: лента, карточки, аналитика (запись запрещена) |

**Регистрация.** На экране входа — вкладка «Регистрация»: имя, завод, e-mail, пароль.
Заявка попадает в админку со статусом «Ожидает подтверждения» — войти до подтверждения нельзя.
В админке: «Подтвердить», «Заблокировать», сменить роль, сбросить пароль, удалить пользователя
вместе с его данными. Там же переключатели:

- **Регистрация открыта** — выключите, и новые заявки приниматься не будут (учётки создаёте вы).
- **Требовать моё подтверждение** — выключите, если ссылка только для своих.
- **Роль новым пользователям** — по умолчанию «Менеджер по тендерам».

Пароль меняется кнопкой «ключ» в левом нижнем углу.

**Первый вход:** `owner@zavod.ru` / `demo1234` (администратор с демо-данными).
Смените пароль сразу после установки.

## Источники данных: как включить реальный сбор

Раздел **«Источники данных»** в интерфейсе — там включаются каналы поступления закупок.

| Источник | Что делает | Когда работает |
|---|---|---|
| ЕИС • 44-ФЗ / 223-ФЗ | живой поиск по zakupki.gov.ru, разбор карточек (номер, НМЦК, ОКПД2, регион, дедлайн) | нужен **российский IP**: zakupki.gov.ru блокирует зарубежные адреса |
| Папка `inbox` | берёт XML ЕИС и CSV/Excel-выгрузки ЭТП из папки и разбирает их | работает всегда, из любой сети |
| API площадки | запрос к API ЭТП по договору (адрес + Bearer-токен) | если у вас есть доступ к API площадки |

**Три способа получать закупки:**

1. **Живой поиск ЕИС** (нужен российский IP). Включите «ЕИС • 44-ФЗ», задайте ключевые слова
   (`задвижка, затвор, арматура`), число страниц и минимальную сумму → «Собрать сейчас».
2. **Выгрузки площадок.** С Росэлторга, B2B-Center, ЭТП ГПБ, ТЭК-Торга экспортируйте закупки
   в Excel/CSV и перетащите файл в раздел «Источники данных» (или положите в папку `inbox`).
   Колонки распознаются автоматически: номер, наименование, заказчик, НМЦК, регион, дедлайн, ОКПД2.
3. **XML ЕИС.** На странице закупки на zakupki.gov.ru есть «Скачать XML» — файл грузится так же.

Дальше всё автоматически: дедупликация по паре «площадка + номер закупки», ИИ-отсев новых
(без расхода токенов на явно неподходящие), попадание в ленту, при включённом Telegram —
уведомление по вердикту «идём». Журнал сбора — там же, внизу страницы.

**Расписание.** «Автоматический сбор по расписанию» + интервал в минутах: приложение само
обходит источники и присылает новое. Пока приложение запущено.

**Telegram-уведомления.** Создайте бота в @BotFather, вставьте токен, узнайте свой chat_id
у @userinfobot → «Сохранить настройки» → «Проверить уведомление».

## Постоянный адрес: сервер или VPS в России

Локальный `start.bat` даёт доступ только с вашего компьютера, а туннели меняют адрес при
каждом перезапуске. Чтобы ссылка была постоянной, приложение ставится на сервер.

**Docker (рекомендуется)** — на VPS в РФ (например, Timeweb, Selectel, Reg.ru, от ~300 ₽/мес):

```bash
git clone https://github.com/bobra2019-dot/tenderpilot.git
cd tenderpilot
cp .env.example .env      # впишите PUBLIC_URL=https://ваш-домен.ru
docker compose up -d --build
```

Приложение поднимется на порту 8000, база и папка `inbox` лежат в папке проекта
(не теряются при обновлении), автоперезапуск при сбое — включён.
Сайт будет доступен по `http://IP-сервера:8000`, а после привязки домена — по вашему адресу.

**Без Docker** — на сервере с Python 3.12+:

```bash
pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Для постоянной работы оберните в systemd (`Restart=always`), а на домен поставьте
Caddy или nginx с HTTPS (Caddy получает сертификат сам):

```
ваш-домен.ru {
    reverse_proxy 127.0.0.1:8000
}
```

Почему сервер в России: ЕИС не отдаёт данные зарубежным адресам — с российского VPS
живой поиск закупок работает.

**Если сервер зарубежный (например VPS в Нидерландах).** ЕИС не откроется напрямую — нужен
российский IP только для запросов к `zakupki.gov.ru`. В интерфейсе: «Источники данных» →
ЕИС • 44-ФЗ → поле **«Прокси для ЕИС»** — укажите российский HTTP/SOCKS5-прокси
(`http://логин:пароль@185.10.10.10:8888`). Или переменная окружения в `docker-compose.yml`:

```yaml
    environment:
      EIS_PROXY: http://логин:пароль@185.10.10.10:8888
```

Где взять прокси: российский VPS за 200–400 ₽/мес с 3proxy/squid, либо готовый
российский residential/datacenter-прокси. Весь остальной трафик (интерфейс, база, LLM)
идёт напрямую — через прокси ходят только запросы к ЕИС. Выгрузки XML/CSV и API площадок
работают без прокси из любой страны.

## Демо-версия на GitHub Pages

Каталог `docs/` — статическая сборка для GitHub Pages: тот же интерфейс, но без сервера.
Данные (23 закупки, профиль завода, предрасчитанные заключения) лежат в `docs/data.js`,
а скоринг и расчёт маржи перенесены в браузер (`web/static-api.js`), поэтому профиль
и калькулятор экономики работают вживую.

Пересобрать после изменения базы или кода:

```bash
python build_static.py
```

Включить на GitHub: Settings → Pages → Source: **Deploy from a branch**,
branch `main`, папка **`/docs`** → Save. Сайт появится по адресу
`https://<логин>.github.io/<репозиторий>/`.

Что есть в статической версии: весь интерфейс, лента с фильтрами, карточки закупок,
профиль завода с пересчётом оценок, калькулятор маржи, воронка, аналитика.
Чего нет: живого LLM-анализа (нужен сервер с ключом), разбора ссылок и файлов ТЗ,
реального мониторинга площадок — для этого нужна полная версия.
